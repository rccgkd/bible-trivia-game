# Kingdom Quiz

A host-led trivia game for church game nights, built as a free website. One
device (a laptop or PC, ideally projected on a screen) runs the game; anyone
in the audience can join from their own phone to vote during "Ask the
Audience."

Two question categories are built in:

- **📖 Bible** — 600 questions covering names, places, numbers, speeches, and
  events across the whole Bible, from Genesis to Revelation.
- **⛪ Church History** — 150 questions covering the story of the Christian
  faith from the Day of Pentecost through the modern era, across all major
  traditions.

Every Bible question's answer is followed by the full King James Version
verse it comes from. Every Church History question is followed by a short,
factual explanation.

## 1. How to Play

### Getting started
1. Open the site. Choose **Host the Game** (on the main screen/projector) or
   **Join as Audience** (on your own phone).
2. Both roles see a short illustrated tutorial screen first — no need to read
   anything else before playing.
3. The host then sets up the game: number of players (1-4), question
   category, and how many questions each player will answer.
4. Starting the game creates a 4-character **room code**, shown at the top of
   the host's screen. Audience members type this code in on their phones to
   join.

### Turns and scoring
- Players take turns answering one question at a time, going around the
  group in rounds (everyone answers question 1, then everyone answers
  question 2, and so on).
- ✅ Correct answer: **+10 points**
- ❌ Wrong answer: **−5 points**
- ➖ Pass: **0 points**
- After every answer, a pop-up shows the point change and the player's
  running total. Only the host advances the game.

### Lifelines
Each player gets each of these **once per game** (not once per turn):

- **➗ 50:50** — removes two of the four wrong options.
- **📞 Phone a Friend** — a 30-second timer to consult someone off-screen.
- **🙌 Ask the Audience** — opens a 20-second live vote to everyone connected
  on their phones. Results appear on the host's screen as a vertical bar
  graph of live percentages, and the options on the host's own screen glow
  in proportion to the votes too.

Once a player uses a lifeline, it's gone for the rest of the game — for that
player only. Other players still have theirs.

### Winning
Once every player has answered all their questions, the game ends and a
ranked leaderboard (best to last) is shown, with the top scorer crowned. The
host can start a **Rematch** (same players, scores reset) or a **New Game**
(back to setup).

### Mid-game controls
- **🏠 Home button** (top right): leave the current game/session, with a
  confirmation prompt.
- **↺ Restart Game** (below the lifelines): resets scores and lifelines
  immediately, without waiting for the game to finish.
- **🔊 Mute button** (top right): toggles all sound effects.

## 3. Hosting It (GitHub Pages)

1. Create a free account at **github.com**, if you don't already have one.
2. Click the **+** icon → **New repository**. Name it (e.g.
   `bible-trivia-game`), set it to **Public**, and don't add a README (this
   one already exists).
3. On the empty repo page, click **"uploading an existing file"** and drag in
   the entire contents of this folder — `index.html`, the `css` folder, and
   the `js` folder (keep the folder structure intact). Commit the changes.
4. Go to **Settings → Pages**. Under "Source," choose **Deploy from a
   branch**, branch **main**, folder **/ (root)**. Save.
5. After about a minute, refresh — you'll see a green box with your live
   link: `https://<your-username>.github.io/<repo-name>/`.

At this point, **Host the Game** already works fully on its own — you can
play a complete solo round with no further setup. Only the audience-voting
feature ("Ask the Audience") needs the next step.

## 4. Setting Up Firebase (for live audience voting)

Firebase lets phones in the audience vote live. Free tier is enough for a
church-sized crowd.

1. Go to **console.firebase.google.com** and create a project (Google
   Analytics can be switched off — not needed).
2. On the project dashboard, click the **`</>` (Web)** icon to register a web
   app. Skip "Firebase Hosting" (you're using GitHub Pages). Copy the
   `firebaseConfig` object it shows you.
3. **Build → Authentication → Sign-in method → Anonymous** — enable it.
   (Audience members vote without creating an account.)
4. **Build → Realtime Database → Create Database** — choose any location,
   start in test mode.
5. In the **Rules** tab of the Realtime Database, replace the rules with:

   ```json
   {
     "rules": {
       "rooms": {
         "$roomId": {
           ".read": true,
           ".write": "auth != null",
           "lifelines": {
             "askAudience": {
               "votes": {
                 "$uid": {
                   ".write": "auth.uid === $uid"
                 }
               }
             }
           }
         }
       }
     }
   }
   ```

   Click **Publish**. (Plain terms: anyone can *read* a room so the audience
   screen updates live; only a signed-in device can *create or change* a
   room; and each audience member can only write their own vote.)

6. Open `js/firebase-config.js` in a text editor. Replace the placeholder
   `firebaseConfig = { ... }` object with the real one you copied in step 2 —
   leave the three lines below it (`firebase.initializeApp`, `auth`, `db`)
   untouched.
7. Upload the updated `firebase-config.js` back to GitHub (open the file in
   your repo → pencil ✏️ icon → paste the new content → Commit changes).
   Give it a minute to redeploy.

### Testing it
Open the site on the host device and start a game — a room code now appears.
On a phone, open the same site link, choose **Join as Audience**, and enter
that code. Trigger **Ask the Audience** on the host screen and confirm the
phone lights up with voting options and the host's bar graph fills live.

## 5. Troubleshooting

- **"Ask the Audience" stays greyed out** — Firebase isn't connected. Check
  that `firebase-config.js` was saved correctly and that Anonymous
  Authentication is enabled.
- **"Room not found" on a phone** — double-check the code, and make sure the
  host has actually clicked "Start Game" (the room is only created then).
- **Nothing loads right after enabling GitHub Pages** — wait 2-3 minutes;
  the first deploy can be slow.
- **Want to edit anything** (add questions, tweak colors, change wording) —
  every file is plain text. Edit directly on GitHub using the pencil ✏️ icon
  on any file, or download, edit locally, and re-upload.

## 6. Suggested Future Selection Criteria

A few ideas for further ways to let the host filter the question pool,
beyond the current Bible / Church History split:

- **Old Testament vs. New Testament only** (within the Bible category)
- **By book or section** (e.g. the Gospels, the Pauline Epistles, the
  Prophets)
- **By era** within Church History (Early Church, Medieval, Reformation,
  Modern Missions, 20th Century)
- **A "Kids/Family Friendly" easier tier**, separate from the main pool
- **A mixed/shuffle mode** that draws from both categories in one game
- **A "Missed Questions" review mode**, replaying only what a group answered
  wrong, for study/revision purposes

None of these are built yet — just worth considering for a future update.
